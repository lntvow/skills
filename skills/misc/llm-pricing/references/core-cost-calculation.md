# 核算规则

默认值（基准模型、比较集合、币种、时段默认档）以 `SKILL.md`「默认口径」为准；费率来源见 [价格来源](core-pricing-sources.md)。本文件写字段口径、公式与例外规则。

## Token 分类与缓存

样本的门槛见 `SKILL.md` 工作流程第 1 步。这里只处理样本的整理口径：先确认字段定义、统计范围、缓存类别与总量关系；字段口径不明时向用户澄清，不要推测。

不同来源的报表字段命名不一致，不要假定它与官方字段同名同义，也不要按名字「看起来像」就归类。下列任一项无法从样本本身确认时，先向用户确认，不要靠猜字段含义直接套公式：

- 输入类字段是否已包含缓存命中，还是缓存命中单独列项
- 是否单列缓存写入
- 统计范围：单次请求还是区间汇总；是否含思考、工具调用、图片等附加用量（图片、音频、工具调用等非文本项不计入费用，仅用于判断样本是否混杂）

含义不明（判断不出某个数字属于哪一类）必须先确认；样本来源本身带该类别却缺列时（如 OpenAI 报表缺 cache_write_tokens），提示缺项，不计算。来源不含的类别不构成缺项：例如按 DeepSeek 口径（命中 / 未命中 / 输出）提供的样本没有写入列，GPT 行照常计算，不计写入费，并在结论中说明该行是**下限**（可能低估；GPT-5.6 及以后写入价约为普通输入价的 1.25 倍）。币种与时段由「默认口径」兜底，不阻塞计算。

先为每个待比较模型单独核对费率，使用官方精确模型 ID，并按 API 费率口径取价。逐一核实该模型适用的各类单价，包括命中输入、未命中输入、缓存写入和输出；同时检查时段、处理档位、上下文档位及优惠是否适用。不同模型即使属于同一系列，价格也不能默认相同；不得用其他模型的费率填补缺项。只有官方明确说明费率适用于目标模型时才能沿用；适用关系不清时按「取价失败时」处理，不猜测也不给部分数字。

依据样本中的字段定义及官方用量字段说明决定如何加总。不同来源可能把缓存 Token 作为输入总量的子集，也可能单独列项；不要重复计数。

- **命中输入**：使用该模型的 cached-input / cache-hit 单价（DeepSeek 价目页写作「缓存命中」）。
- **未命中输入**：即普通未缓存输入，使用常规 input 单价（DeepSeek 价目页写作「缓存未命中」）。
- **缓存写入**：只有来源明确提供 cache_write_tokens 等写入 Token 数，或用户明确给出相应假设时，才使用 cache-write 单价（DeepSeek 价目页不列此类别）。
- **输出**：使用 output 单价。若来源单列其他计费项目，只有在用户要求且用量数据充分时才加算。

缓存写入是这部分 Token 的计价类别，不是普通输入费之外再加一笔，倍数或附加规则一律以价目页为准，不套用其他模型或旧版本的费率。

- **OpenAI API**：先查汇总价目页，再查目标模型的官方详情页和缓存计费说明；汇总页未列某模型或类别时不能直接判定无价。按精确模型和所选档位的单价计算，若只列倍数则按官方倍数换算。只有官方资料明确该模型没有某计费类别时才不计该项；仍无法确认则按「取价失败时」处理，不自行补价。
- **DeepSeek**：按其当前价目页列出的类别核算，不套用 OpenAI 的写入费规则；价目页未列写入单价时，不增加写入项，也不把未命中数当写入数。

先确认字段是否互斥，再检查总量。仅当字段定义明确、各类别互斥时，才用：

输入总量 = 缓存命中 + 普通未缓存输入 + 缓存写入

若样本同时提供 input_tokens、cached_tokens 和 cache_write_tokens，先确认它们属于同一统计范围；当字段定义确认两个明细都包含在 input_tokens 总量内且互斥时，普通未缓存输入数 = input_tokens - cached_tokens - cache_write_tokens。普通未缓存数已单列时直接使用该字段。不得把总 input_tokens 与缓存命中、写入明细重复相加；若字段口径不符、差额为负或关系不明，保留原字段并指出问题，不要强行调平。

### 数据缺失时

样本缺少其来源应有的某一类 Token 数时（如 OpenAI 报表未给写入量），直接说明缺哪一项，不输出费用、倍数或总价；只有用户明确要求按某个假设继续时，才按其要求计算并标注为假设。来源本身不含的类别不算缺项（见上文：DeepSeek 口径的样本无写入列时，GPT 行按不计写入费计算，该行按下限理解）。

- 不要把缺项按 0 计，也不要把缓存未命中数当成写入数。
- 模拟样本时不要推断另一模型会写入多少缓存，也不要把原供应商的「未命中」等同于 OpenAI cache_write_tokens。

### 缓存写入费

只对官方列出写入价的模型计入；价目页写入列为空的模型（如 GPT-5.5 及更早）不适用，不要另加。

- 样本未提供写入量时：不推算、不计入，并在结论中说明该 GPT 行是**下限**（可能低估）。
- 默认不给估算值。用户明确要求估算写入费时，才给**敏感性区间**（如命中量的 0% / 5% / 10%），说明占比取决于缓存条目复用次数，不给单一估计值。
- 能拿到含 cache_write_tokens 的真实 usage 时，优先用真实数据，不做推算。

## 计算

样本是用量模板：比较时把同一份用量依次套到每个待比较模型上，得出「同一使用情况在各模型下的费用」；不要按供应商或模型归属拆分样本，也不要把同一份用量重复加总。

多份样本先汇总再计算：用户提供多份样本（如按月份、按任务给两份用量）时，先把各份的同类字段换算成同一单位后相加，再当作一份样本计算，输出一份合计结果；只有用户明确要求时才逐份分别计算并分别输出（每份都带样本行与口径）。

先把样本单位统一为 token：样本可能以 K、M 或「千 token」等不同单位给出，不要直接相加或代入公式。对每个字段完成单位换算后再计算，并在结论中注明原始单位与换算方式。

将 Token 数换算为百万 Token：

百万 Token 数 = Token 数 / 1,000,000

各 Token 类别必须互斥，并且只计算该模型官方价格页列出的文本 Token 计费类别（图片、音频、embedding、工具调用、微调等不在范围）；若用量字段有重叠，先依据字段定义拆分，避免重复计数。

- **DeepSeek API**：按中国官网在核价时列出的类别计算。

  DeepSeek 费用 = (缓存命中数 × 该模型命中价 + 缓存未命中数 × 该模型未命中价 + 输出数 × 该模型输出价) / 1,000,000

- **OpenAI GPT API**：按目标模型和对应处理/上下文档位列出的类别逐项计算。只有官方费率包含缓存写入项且样本提供对应写入 Token 数时，才计入写入费用；来源不含写入类别时不计入并标注假设；来源含写入列却缺值时按「数据缺失时」处理。

  GPT API 费用 = (普通未缓存输入数 × 该模型输入价 + 缓存命中数 × 该模型缓存输入价 + 缓存写入数 × 该模型写入价 + 输出数 × 该模型输出价) / 1,000,000

若官方价格页对目标模型未列某项，按上一条规则处理；其来源应有的某一类 Token 数缺失时按「数据缺失时」处理。

### 币种与倍数

DeepSeek 直接用中国官网人民币费率。GPT 的美元价按同一次核价读取的 USD/CNY 折算（读 <https://open.er-api.com/v6/latest/USD> 的 `rates.CNY` 和 `time_last_update_utc`；汇率取不到时向用户索取）。所有 GPT 行使用同一汇率；结论注明汇率数值、接口更新时间（换算为北京时间）和本地查询时间，不要把查询日期写成汇率更新时间。DeepSeek 的空闲时段/高峰时段费率不同，按时段分别计算后相加；不要把税费或优惠金算进单价。

相对倍数 = 该模型费用 / 基准模型费用

用户明确指定其他基准时，改用其指定的模型和价格口径；未指定时取「默认口径」。基准显示为 1.00x。内部计算使用原始整数 Token 数和未舍入费率，只在展示时四舍五入。检查总量、汇率方向、单位和除法分母。待比较模型达到 3 个，或结果要用于决策时，必须用脚本把计算独立跑一遍再给结论。

## 该问还是该算

遇到下列情况时先停下，不要一边猜一边算。本表只是速查，细则以对应小节为准。

| 现象 | 动作 |
| --- | --- |
| 字段含义不明（分不清缓存命中 / 普通未缓存输入 / 写入） | 问用户，不按字段名猜 |
| 来源应有的某一类 Token 数缺失 | 不出数字；用户明确要求按某假设继续时，标注为假设 |
| 来源不含的类别（如 DeepSeek 样本无写入列） | 不算缺项：不计该项，并说明结果为下限（可能低估） |
| 只有汇总总量、没有分类分项 | 不计算，先要明细 |
| 官方页面读不到费率、模型或档位对应不上 | 按「取价失败时」处理：整轮不出数字，只说明原因 |
| 官方页面明确没有该类别 | 不算失败，按各供应商规则处理，不增项 |
| 汇率取不到 | 向用户要汇率，不出数字 |
| 字段重叠或差额为负 | 保留原字段并指出问题，不强行调平 |
| 时段无明细 | 按「默认口径」取时段并标注为假设 |

## 取价失败时

取不到官方费率时，整轮不出数字：不输出费用、倍数或总价，也不展示已算出的其他行，只说明原因。

- 算取价失败：官方页面打不开、改版后读不出对应费率、模型或档位对应不上、费率适用范围无法确认。
- 不算取价失败：官方页面明确没有该类别（如某模型不列缓存写入费），按各供应商规则处理。
- 说明内容：取不到的是什么、影响哪些模型或行、需要用户提供什么。不要用其他来源、其他模型或其他档位的费率补齐，也不要给部分结果。

## 结论引用

在结论附近引用对应官方页面。数据不足时就说清楚缺哪一项，不要用估算值冒充账单。
