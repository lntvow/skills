# 多语言写作（Multilingual Authoring）

一份文档要出几种语言，就把它写几遍。

读的人只看其中一种。所以每一版都得像那个语言里长出来的，而不是另一版换过词的影子。逐句译出来的
文字，语法没错、意思也对，但母语者一眼看得出它是翻译——这就是要避免的。

## 什么时候用

- 一份文档要出两个以上语言版本：README、指南、公告、发布说明、API 说明
- 已有一种语言写完了，要补其余语言
- 手上有份译文读着别扭，怀疑是翻译腔

## 什么时候不用

- 只写一种语言
- 只译一小段引用或一句提示，没有第二份要对照
- 术语表、命令清单这类本身就跨语言的表格，照抄即可

## 1. 先定骨架，标题各语言自己写

先定结构：几个章节、什么顺序、哪些内容进表格。骨架共用。

**标题不要互译。** 中文的「这个集合有什么不同」和英文的 「What Makes This Collection Different」、
日文的「このコレクションの違い」，是三个说法，不是一句话的三种拼法。

## 2. 正文各写各的，母版只提供事实

母版（你顺手写的那一版）提供三样东西：要讲哪些事、先后顺序、具体数值和名字。**不提供句子。**

- 中文靠短句、语序和逗号推进，连接词少
- 英文要显式连接（`because`、`while`、`which`），句子可以长，也可以先给结论
- 日文要处理敬体与常体的取舍，以及长定语的堆叠方式
- 其他语言各有各的默认节奏

所以各版的信息密度、句子数量、段落长度本来就不该一样。完全相等是个坏信号。

## 3. 翻译腔：先看通用症状，再看具体语言

通用症状，任何语言都适用：

- 语序跟着母版走，一句话一个从句地搬
- 连接词密度不对：要么满篇「因此、此外」，要么该有的时候一个都没有
- 代词滥用或全缺：母版用 `this` / `it`，译文就跟着写「这」「它」
- 名词化：把动词拆成「进行 + 名词」
- 长定语前置，读者要读到最后才知道主语是什么

中文的症状清单（最常用，列全）：

| 症状 | 长什么样 | 改成 |
| --- | --- | --- |
| 「进行/加以 + 名词」 | 进行配置、加以验证 | 直接用动词：配置、验证 |
| 「被」字句堆叠 | 文件被读取，错误被抛出 | 中性句：读文件；出错就抛 |
| 「的」 连用 | 开发者的代码的质量问题 | 开发时留下的代码质量问题 |
| 长定语前置 | 一个支持多平台的基于 Rust 的编辑器 | 一个编辑器，支持多平台，用 Rust 写的 |
| 「对于……来说」 | 对于新用户来说 | 新用户 |
| 「当……时」密集 | 当请求失败时，当超时的时候 | 请求失败或者超时，就… |
| 「不仅……而且」 | 不仅快，而且稳 | 快，而且稳 |
| 代词直译 | 这、那、它、我们 满篇 | 该重复的重复，该省略的省略 |

其他语言不套这张表，用同一条判断法：**这句话，这个语言的母语者会这么说吗。** 判断不了就往下看。

## 4. 不懂的语言别假装懂

你不懂那个语言的自然度时，两种做法都行，但必须说明：

- 用机器翻译出初稿，然后**按内容重写**，不要交机翻原文
- 直接标注这一版是机翻未校，请母语者过一遍

不要写「已校对」来结束责任。一份读起来像翻译的译文，比没有译文更糟——它会被当成定稿。

## 5. 各版必须一致的，和允许不一样的

| 项目 | 要求 |
| --- | --- |
| 章节层级、顺序 | 一致，方便对照阅读 |
| 表格行列、代码块 | 一致 |
| 命令、路径、标识符、版本号 | 逐字相同 |
| 术语 | 同一概念各版固定同一种说法，或保留原文 |
| 数字与单位 | 一致；中文里数字与汉字之间留空格（如 `100 字符`、`3 个`） |
| 标点 | 各按本语言：中文「」、英文 `""`、日文「」、全角半角不要混 |
| 文件命名 | 主文件 `README.md`，其余 `README.<语言标签>.md`（如 `README.zh-CN.md`、`README.ja.md`） |
| 句子数量、段落长度、信息密度 | **允许并且应该不同** |

技术名词一般不译：`try/catch`、`Token`、`timeout`、`commit`、`submodule` 保持原样。译名不统一比不译更糟。

## 6. 完稿前逐版检查

版本一多，最容易漏整节。按这几条走：

- 只读某一版：能不能不靠别的版本就看懂？
- 各版的章节数量对不对得上？（数一下标题行，别靠印象）
- 术语表里每个概念，各版都一致吗？
- 改了一版之后，其余几版跟改了吗？
- 语言切换的那一行，各版都指向其余所有版本吗？

## 例：同一个意思，两种句子形状

**英译中。** 原文（英文，正常写法）：

> Skills load on demand, so an agent never pays for context it does not use.

照着句子搬：

> 技能是按需加载的，所以 agent 永远不会为它不使用的上下文付费。

中文里会这么写：

> 技能按需加载，用不到的上下文不花钱。

差别不在词。中文可以不要那个「所以」——顺序本身已经说明了因果；`it does not use` 也不必写成
「它不使用的」这种前置定语。

**中译英。** 原文（中文，正常写法）：

> 打包前先清掉 `dist`，免得把旧产物打进 VSIX。

照着句子搬：

> Before packaging first clean `dist`, avoid to pack old output into VSIX.

英文里会这么写：

> Clean `dist` before packaging, so stale files can't end up in the VSIX.

中文条件在前、目的在后；英文先把动作说出来，目的用 `so` 挂在后面。「免得」不是 `avoid to`，
`old output` 在英文里也更常说 `stale files`。

两个方向都不是换词，是把句子重排一遍。
